## 1. 指挥依据与目标

本计划复用了本机 WorkBuddy 的 SEO 专家角色配置：`/Users/myd/.workbuddy/plugins/cache/experts/seo-expert/1.0.2/agents/seo-expert.md`。这是读取并应用其工作方法，没有远程启动或联系原 WorkBuddy 会话。采用其用户意图优先、先取证、技术与内容共同推进的方法；其中预设的排名、转化率、外链数量等通用示例不是本站已有数据，也不是本站保证达到的结果。其 FAQ / HowTo 建议按最新官方资料作了修正。

目标是让需要浏览器环境管理、隐私检测与自动化的访问者找到可验证的答案，完成比较和选型。有效成果按非品牌自然搜索点击、有效阅读、比较页访问和产品官网点击衡量。EasyBR 是关联产品，必须公开披露；BrowserHub 要允许用户按实际需求选择任何适合的产品。

增长假设：先用可操作、可引用的中英文指南和决策清单建立主题覆盖，再用原创验证记录与可复用资料赢得引用；根据搜索后台真实 query 改进页面。页面数、字数、schema 数量不能替代有效流量。

## 3. 纠正上文 WorkBuddy 结论

1. **品牌搜索未看到网站，不能证明未收录或“权重为 0”。** Google 明确说明 `site:` 结果也并不穷尽；索引诊断应看 URL Inspection、Page indexing 和 Google 选定 canonical。“品牌第一”只能是观察目标，不能承诺。[Google site: 文档](https://developers.google.com/search/docs/monitor-debug/search-operators/all-search-site)
2. **GSC 和 sitemap 是诊断与发现手段，不是有任何自然流量的必要条件。** 提交 sitemap 不保证抓取、索引或排名。建设内容和修复技术可以同步推进，不应一直等账号权限才开始。[Google 抓取与索引 FAQ](https://developers.google.com/search/help/crawling-index-faq)
3. **没有可验证的量和 KD，不能称某个词“搜索量最高”或“最容易赢”。** 本轮搜索返回商业榜单、厂商博客和社区问答，足以证明存在多种内容形态，无法推导需求规模，也不是固定地区、设备、引擎的可靠排名快照。上文“前排全是新站内容农”“外链≈0”没有足够证据，本计划不采纳。
4. **不以 2000–3000 字作为验收门槛。** 参考竞品如何解决问题、解释边界和出示证据；不要扩写重复语句。必须增加决策信息、可复现步骤、独立引用或原始记录。Google 要求对已有来源提供实质增量。[Google 内容质量指南](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)
5. **FAQ / HowTo 不是 AI 引用捷径。** 2023 年 FAQ 曾限知名政府及健康站，但这一状态也已过时：Google 最新更新记录说明 FAQ 富结果自 2026-05-07 起不再展示，2026-06-15 删除相关文档。HowTo 富结果则已于 2023-09 停用。普通问答仍可帮助读者，结构化数据必须与可见正文相符；不把新增 FAQ 标记当增长成果。[Google 2026 更新记录](https://developers.google.com/search/updates) · [HowTo 停用公告](https://developers.google.com/search/blog/2023/08/howto-faq-changes)
6. **AI Search 不要求特殊 schema 或 llms.txt。** Google 的 AI 搜索沿用基础 SEO，要求页面具备被索引与展示摘要的资格。其 2026-06-15 更新进一步明确 llms.txt 不会正面或负面影响 Google 搜索可见性和排名；可为其他工具维护，不承诺引用。[Google AI 搜索文档](https://developers.google.com/search/docs/appearance/ai-features) · [Google 更新记录](https://developers.google.com/search/updates)

## 4. 本轮实施指令：按此顺序验收

### P0：只把完整内容作为搜索落地页

- 先把新增内容完整制作成英文和简体中文。已有五语回退英文的指南保留可访问 URL，但暂不索引，移出 sitemap 与有效 hreflang 集合；明确链接到英文原文。完整翻译并审校后再恢复索引。
- 无前缀中文指南指向 `/zh-cn/guides/<slug>/` 的规范地址，内部链接、hreflang 与 sitemap 使用同一套 canonical。`noindex` 是排除页面的指令，canonical 是规范化信号，不把前者当成保证传递所有信号的办法。
- 多语言质量门槛看正文、导航、图表、表格与 CTA 的实际语言，不只检查 `lang` 属性。Google 主要通过可见内容识别语言。[Google 多语言网站指南](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)
- 每次发布同时抽查正式域与源站 HTML，检查缓存、HTTP 状态、canonical、robots、可见文章和引用。

### P0：建立可信的编辑与商业关系说明

- about/编辑说明写清公开资料整理、实测与未测试三类证据；说明 AI 可协助起草，但上线前逐条核验。标记 BrowserHub 与 EasyBR 的关系，不自称完全独立或中立。
- 未实际完成测试，不得写“我们测了”“通过率”“最安全”“完全不可检测”。不得把目录星级包装成第三方用户评分。无明确方法学的星级应撤掉或清楚标为主观目录标签；不新增假 review / aggregateRating。
- 文章显示真实维护团队和编辑日期，逐条引用官方资料。不要编造作者姓名、认证、工作年限、使用经历。
- 价格与免费额度保留币种、计费周期、地区/促销条件、官方 URL 和实际核验日期。无法核验的项目写“待核验/以官方为准”，不把全站编辑日期伪装成价格检查时间。

## 5. GEO 与搜索抓取的实际工作

Google：保持 Googlebot 可抓取、正文文字可解析、摘要未被意外禁止；不为 fan-out query 批量复制近似文章。Google 也明确提醒：大量相似页面并不提高质量，主要为操纵排名或 AI 响应生成内容可能构成 scaled content abuse。[Google AI 内容建议](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)

Bing / Copilot：验证主域、提交只含规范且可索引 URL 的 sitemap；内容新增/实质修改/删除时通知 IndexNow，记录提交与实际索引两种状态。IndexNow 是发现通知，不是收录保证。[Bing Webmaster Guidelines](https://www.bing.com/webmasters/help/webmaster-guidelines-30fba23a) · [Bing URL 提交](https://www.bing.com/webmasters/help/URL-Submission-62f2860b)

ChatGPT Search：允许 `OAI-SearchBot` 并检查其官方 IP 的真实请求。`GPTBot` 属于训练控制，和搜索可见性独立；不因为想要搜索流量就替用户改变训练偏好。仅改 robots 不能证明 CDN/WAF 放行。[OpenAI 爬虫文档](https://developers.openai.com/api/docs/bots)

保留与可见正文匹配的 Article / Breadcrumb / WebSite / Organization 等 schema；首页品牌名称、域名、项目介绍保持一致。现有代码已含 WebSite，先验证，不重复堆节点。[Google 网站名称](https://developers.google.com/search/docs/appearance/site-names)

sitemap `lastmod` 根据每篇实质变化维护；不能每次部署全站刷日期。Google 不使用 sitemap 的 priority 和 changefreq 做排名杠杆。[Google sitemap 构建](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)

GEO 内容标准：重要事实紧邻来源；表格说明比较口径；结论写成带条件的完整句；公开未知；给出日期与版本；链接可复现记录。每月在固定的 10 个问题、固定语言/地区与记录日期下抽样查看 AI 引用。引用次数仅是样本指标，不能称全网“AI 占有率”。

## 6. 数据接入与验收方法

### 不等账号也能完成的交付

构建/静态校验；链接与 canonical 检查；robots/sitemap 抽样；主域与源站版本复验；来源事实核对；页面移动端可读性；语言质量检查。产物检查应按“内容是否真正翻译”变化，不能强制每个语言都必须列出同一批 URL。

### 需要站主现有账号的工作

先查是否已有 GSC 与 Bing 验证，避免重建重复 property；有权限即提交 sitemap、抽查代表 URL。只有无法取得必要验证时才由站主处理 DNS 或在自己的已登录账号里授权；不索取密码。

GSC 每周导出 query / page / country / device，区分品牌 `BrowserHub|EasyBR|ebrower` 与非品牌；查看 7/28/90 天点击、曝光、CTR、平均位置及索引排除原因。品牌分类表达式要在看到真实 query 后修正，隐藏 query 带来的合计差异应注明。

站内测量先核实既有分析工具；没有时选择最少数据采集的方案。事件规范：`guide_to_comparison`、`comparison_to_product`、`outbound_official`，附 language、content_slug、browser_slug 与 link_position；不得记录 Cookie、账号、代理密码。EasyBR 官网点击只是 referral intent，不是安装或付费；有跨站实测归因后才报告安装/付费转化。新增分析需同步隐私说明。

每周看三层：技术完成率 → 搜索发现/曝光 → 有效点击和任务完成。不要把 crawler 请求当真人访问，或把 GitHub 来访计入自然搜索。

第 30 / 60 / 90 天复盘至少包含：优先页面数、可索引页面数、GSC 报告中的已索引数、页面排除原因、品牌与非品牌点击、着陆页分布、搜索到官网点击路径、已验证外部引用及新增内容成本。不要把 sitemap 全量已索引率当唯一目标；被有意排除的重复/未翻译页不是失败。

技术期望：优先页面零错误 canonical、零软404、零孤立页、无正文语言错配。性能优先看足够样本的真实用户 CWV；没有字段数据时标未获取，并用实验室测试排查，不能把 Lighthouse 分数当 field data。

流量期望：第 30 天有可复核基线，第 60 天知道哪些 query/页面正在获得曝光，第 90 天能够用同口径窗口评估增长。暂不设“月访问过万”“品牌必第一”“top3占30%”等缺乏起点的承诺。若数据不支持增长，保留失败结论并改变优先级。

## 8. 内容和权威积累纪律

- 竞品参考对象是其页面结构、用户问题和可检验事实，不抄表达、截图、评分、测试数据和结论。厂商博客也可提供其自家产品事实，不能作为证明其自家排名第一的独立证据。
- 可链接资产优先：带版本的价格/限额公开记录、明确证据等级的兼容性矩阵、可复现检测记录、团队试用评分表。未做测试前只发布方法和空表，不伪造结果。
- 合理完善已有 GitHub/Gitee 资源库到本站指南的相关链接；外部社区只在允许且与问题相关时贡献资源，不买链接、不批量发帖、不建站群。
- 本任务未授权向站外人群发信或私聊；可准备引用资产与目标名单，但实际外联需单独明确授权。不要把未发送的外联计为成果。
- 不按第三方“毒性分数超过5%”机械 disavow，不设必须买到多少高DR链接的指标。
