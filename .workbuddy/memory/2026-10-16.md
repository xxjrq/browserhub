# 2026-10-16 BrowserHub 每日 SEO/GEO 循环

## 巡检结论：昨天的内容建设「几乎完全没上线」

昨日 backlog 清零的判断有误。50 个 guide sections（10464 字）只写在 legacy 路由
`/guides/[slug]` 上，而 **sitemap 提交的 956 条 URL 里 legacy 非locale URL 数量为 0**，
全部是 `/[locale]/...` 前缀。也就是说内容确实存在、curl legacy 路由也能看到，
但搜索引擎收录的 URL 一条都渲染不出来。

## 定位到的 3 个真实 bug

1. **locale 路由完全忽略 `item.sections`**（最严重）
   `src/app/[locale]/[[...segments]]/page.tsx` 的 guides 分支只渲染
   `<Card>` + 一段 `item.content`（约 100 字），从不读 sections。
   → 12篇 × 7 语言 = 84 个 URL 的正文全部缩水约 90%。

2. **locale 路由 h1 未本地化**
   h1 直接用 `item.title`（中文源），所以 `/en/guides/*` 的 h1 是中文
   「浏览器指纹是什么」；且 `CardTitle` 又重复渲染一次 h1。
   → 与 title/hreflang 承诺的语言不一致。

3. **对比页 section 标题写错变量**
   `{item.sections?.map(...)}` 里 h2 用的是 `copy.scenarios` 而非 `section.heading`，
   导致 zh-cn 页连续出现两个「场景建议」。

## 教训（写给明天的我）

- **验证必须针对 sitemap 真正收录的 URL**。昨天 curl `/guides/xxx/`（legacy）看到 9 个
  h2 就判定成功，但 legacy URL 根本不在sitemap 里。以后先确认「这条 URL 会被收录吗」，
  再验证它的内容。
- `grep -c '<h2'` 对压缩成单行的 HTML 只能返回 1，必须用 `grep -o '<h2' | wc -l`。
- 判断内容厚度要按「页面类型 × 语言」聚合统计，而不是抽样单页；抽样会掩盖整类页面的问题。
- 判断中文泄漏不能只统计 CJK 字符数——ja/ko 页面天然含汉字。正确做法是拿
  zh-cn 源文案做子串匹配。
- 顺带发现：任何渲染在 root layout 的组件（footer/header）都会出现在全部
  956 个本地化页面上，改动时的影响面远大于单个详情页。
